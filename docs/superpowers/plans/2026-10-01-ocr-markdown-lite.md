# Plan: markdown-lite layout extraction on a CPU-maximised per-page OCR pipeline

**Date:** 2026-10-01 · **Status:** ready for implementation (pending the human-review items in §10)
**Scope:** `knovas-extract-python` (library), `KnovasComponents/RemoteController` (RC), `KnovasComponents/KnovasPlatform` (admin ingestion + hit context), `KnowledgeBase` (server contract tests, one small flagged server change, Alloy models + Golden Invariants)
**Companion documents:**
- diagnosis — `KnovasComponents/docs/superpowers/specs/2026-10-01-fiduciary-search-diagnosis.md`
- server-side audit — `KnowledgeBase/docs/superpowers/audits/2026-10-01-fiduciary-search-audit.md`
- extractor findings + benchmark harness — `knovas-extract-python/docs/ocr-and-tables-findings.md`, `knovas-extract-python/bench/ocr/`
- vision/mission alignment record — `KnowledgeBase/docs/superpowers/audits/2026-10-01-fiduciary-plans-alignment.md`
- Alloy models — `KnowledgeBase/knovas-software/models/alloy/data_plane/{ocr_budget_failsoft,page_break_provenance}.als`, mechanisms `mechanisms/client_pipeline.als`; invariants GI-EXTRACT-01..05, GI-INGEST-17

This plan was produced by a judged merge of three independent designs (accuracy-first, throughput-first, testability-first) and then reviewed by three critics (regression, performance/operations, security + test adequacy). **Every blocker and major finding of the critics is folded in below** and marked `[C-…]`; the raw critiques are preserved in §12 for traceability. Numbers are from the committed benchmark (`bench/ocr/results/tables.md`) and the layout prototype; all are **synthetic** (reportlab renders + simulated degradations) — real anonymised customer samples are a release gate (§8), not an assumption.

---

## 0. The constraint that shapes everything

**No new GPU or CPU capacity.** OCR runs on the customer's RC host, one document at a time, inside the RC's existing forked extraction child; the server is not changed for this plan beyond tests and one small flagged fix. Development compute is capped too: **no further benchmark grids** — any future measurement is one named configuration against a committed baseline, ≤ 15 min, with elapsed time printed.

## 1. What changes, in one paragraph

`knovas-extract` gets (a) a **per-page OCR decision** with a garbage-text-layer gate, a tesserocr in-process engine (CLI and MuPDF fallbacks), native-dpi ≤ 300 gray rendering, numpy autorotate/deskew/rule filtering, `OMP_THREAD_LIMIT=1`, a bounded **fail-soft** scheduler and an injectable cache; and (b) an opt-in **`text_mode="layout"`** that renders each page from word boxes into *markdown-lite* — `#` headings, reading-ordered paragraphs, one table row per line with ` | ` cells and compact-folded numeric cells, `Key: value` forms, `- ` lists — **as `Page.text` itself**, so every offset/sentence contract holds and the markdown-expansion guard that parks mixed PDFs today is never reached. Unstructured pages are emitted **byte-identical to plain mode** (the law-firm guarantee, GI-EXTRACT-03). The RC immediately stops asking for `emit_markdown` (−8 s/doc, no more `skip:unconvertible` from `check_expansion`, no PolyForm-NC `pymupdf-layout` in the customer image), then adds `RC_PDF_TEXT_MODE=plain|shadow|layout`, page-break markers (`\f`) in the uploaded snippet, partial/retry recording instead of parking, an OCR disk cache with document-keyed purge, and a hash-gated re-ingest wave. The server already consumes `#`, `\n\n`, `\n` and `\f`; it needs a contract test and one small flagged fix (heading-context token budget). Measured on the synthetic Swiss corpus: status quo CER 0.575 / 15 % of amounts recovered → **CER 0.025 / 94 %** at 82–129 pages/min on 4 cores.

| D12 | Row lint applies **only to lines the renderer classified** as header/row/kv | substring `": "` detection | `[C-reg-6]` the prototype mangled prose containing a colon on structured pages |
| D13 | Shadow mode = **one OCR pass, two renderings** (`extract_words()` + plain/layout renderers; `text_mode="both"` internally) | two `extract()` calls | `[C-sec-5]` double OCR CPU and doubled timeout risk for the whole shadow week |
| D14 | Server heading-context budget fix is **required, flagged**, same PR as the contract test | "optional" | `[C-reg-4][C-sec-1]` the server prepends `hc: ` *after* splitting to 248 tokens; long titles/paths silently truncate the last row's amounts in ml-embedder |

## 3. OCR pipeline (knovas-extract `_ocr/`)

**Backends** (`backend.py`, `select_backend(engine="auto")`): `TesserocrBackend` (tesserocr ≥ 2.11,< 3, MIT; manylinux wheel bundles Tesseract 5.5.1 + Leptonica; one persistent `PyTessBaseAPI` per worker, `preserve_interword_spaces=1`, `SetSourceResolution`, `SetImageBytes` on raw gray bytes, `Recognize(timeout)`, `GetTSVText`) → `CliBackend` (`tesseract stdin stdout … tsv`, PGM on stdin, **minimal explicit env**, `stderr=DEVNULL`, `timeout=ocr_page_timeout_seconds`, `close_fds=True`; `# nosec B603 B607` with justification) → `MupdfBackend` (`get_textpage_ocr(language, dpi=300, full=True)`; alone it fixes the 72-dpi defect at `pdf.py:393`). Chosen backend + version in `metadata.extra["pdf:ocr_backend"]`. Models: `tessdata_fast` from the Debian packages in the RC image (`tesseract-ocr-{deu,eng,fra,ita}`), `TESSDATA_PREFIX` set; `tessdata_best` is an optional tier (no gain on clean print, 1.6–2.5× CPU).

**Per-page decision** (`decision.py`): D9 above, as the pure function `decide_page(text, image_cover, use_ocr) -> OcrDecision(needs_ocr, keep_text_layer, reason)` wrapped by `page_needs_ocr(page, use_ocr)` (text from `page.get_text("text")`, image cover from `get_image_info()` bboxes clipped to the page). A **second-chance** re-OCR for a structured page whose text layer yields no row-aligned lines while raster rules exist (counted). Pinned by `ocr_budget_failsoft.als` (`PerPageOcrDecisionMechanism`, mutant `ocr__document_level_decision` = today's behaviour) and `tests/unit/test_ocr_decision.py`.

**Render + preprocess** (`preprocess.py`, numpy + Pillow only): `render_dpi = min(300, native_dpi)` rounded to 10 (never upsample: fax150 at 300 dpi CER 0.145 vs native 0.028); gray, `alpha=False`, raw samples (never PNG); sideways check by ink-run variance → OSD only when sideways → rot90k; projection-profile deskew ±3° applied when |angle| ≥ 0.15°; rule/dot-leader detection by 1-D run-length opening with the image kept intact, rule-overlapping words dropped after OCR; Otsu left to Tesseract; `maxchan` colour dropout behind `colour_dropout=False` until the stamp fixture confirms it. **New `[C-sec-2]`:** `Limits.max_ocr_image_megapixels` (default 40) checked from `get_image_info()` before any render — over-limit pages are skipped with a counted warning; `fitz.TOOLS.store_shrink(100)` after each render `[C-perf-6]`; prefetch 1 × workers pixmaps.

**Recognition**: psm 3, one psm-4 retry when psm 3 yields < 50 % of the rows expected from detected rules or mean conf < 70 with ink ≥ 2 %. TSV level-5 words → `OcrWord(text, bbox in pt, conf, block, par, line, line_h)` through `frame_to_page`.

**Parallelism**: `os.environ.setdefault("OMP_THREAD_LIMIT", "1")` before tesserocr loads **and** `ENV OMP_THREAD_LIMIT=1` in the RC image; **verified in the RC image build job** (1 vs 4 workers on a 4-page fixture: CPU/wall ≤ 1.3, speed-up ≥ 2.0) `[C-sec-17]`, with `pdf:ocr_cpu_seconds` emitted next to `pdf:ocr_seconds`. Workers derived from `len(os.sched_getaffinity(0))` and `/sys/fs/cgroup/cpu.max`, default `max(1, cores − 2)` inside the sync window and `cores − 1` outside it; the extraction child runs at `os.nice(10)` `[C-perf-2]`; the pool is **sized lazily** (`min(configured, pages needing OCR)`, API created on first task) so a one-page scan pays one init `[C-perf-3]`; a long-lived scheduler-owned worker pool is the M4+ follow-up. Render stays on the calling thread (PyMuPDF documents are not thread-safe). Pages are submitted in document order and reassembled by index → byte-identical output for 1 vs N workers.

**Budgets and fail-soft** (`pool.py`, `run_ocr_schedule`): `Limits.max_ocr_pages=500`, `ocr_time_budget_seconds=240` (`[C-sec-0]` the RC derives it as `timeout − workers × ocr_page_timeout − render margin`), `ocr_page_timeout_seconds=60` (hard on CLI/process pool, advisory on in-process), `max_ocr_workers=8`. The scheduler stops *submitting* when a budget trips; the remaining candidates are `skipped` and counted; a page exception/timeout is a `failed` page with empty text; extraction **succeeds**. On a budget trip the RC child **hands over the partial result immediately and exits without joining the pool** (`shutdown(wait=False, cancel_futures=True)` / `os._exit`) `[C-perf-1]`. Pinned by `ocr_budget_failsoft.als` (`BoundedOcrMechanism`, `NoSpuriousSkipMechanism`, `FailSoftMechanism`; mutants `ocr__spurious_skip`, `ocr__budget_raises`) and `tests/unit/test_ocr_scheduler.py` (fake backends, fake clock — no Tesseract).

**Cache** (`IOcrCache` protocol, library never writes files): key per D5; default per-document dict. RC `OcrDiskCache` (SQLite next to `RC_SYNC_STATE_PATH`, LRU, `RC_OCR_CACHE_MAX_MB=512`, **`0` disables**, opened only in the forked child, created `0600`, **document index table so entries are purged on delete/unsync/path removal and on `reset`**, retention documented) `[C-sec-10]` — this is GI-EXTRACT-04.

**Observability**: `pdf:ocr_pages`, `pdf:text_pages`, `pdf:ocr_pages_skipped`, `pdf:ocr_backend`, `pdf:ocr_seconds`, `pdf:ocr_cpu_seconds`, `pdf:ocr_mean_conf` (scalars only; spec 1.3.0 schema unchanged) and **one** counted warning "pdf: OCR applied to N of M pages via <backend>". `[C-sec-8]` the RC refuses to mark a PDF unconvertible when `pdf:ocr_backend` ≠ the configured engine or `ocr_pages_skipped == ocr_pages`, emits `rc_ocr_backend_degraded_total`, and the RC image CI asserts `select_backend().name == "tesserocr"` on the mixed fixture.

**Throughput accounting** (4 idle cores): decision 0.5 ms, cache lookup 0.1 ms, render 22 ms, autorot 13 ms, deskew 48 ms, Tesseract fast deu+eng 1.1–1.6 s single-thread, layout 2–3 ms; digital page 10–50 ms. ≈ 3 pages/s on 4 cores, ≈ 6 on 8; a 100-page scan ≈ 35–60 s; a 300-page scan ≈ 2.5 min inside the child timeout; beyond that, partial + nightly backfill.

## 4. Markdown-lite (`_layout/`, `text_mode="layout"`)

**Carrier**: the renderer output **is** `Page.text`; `content.text = canonicalize_text("\n\n".join(page_texts))` exactly as today, so `Page.line_start/line_end`, `split_sentences_for_pages` and `_assert_consumer_contracts` apply unchanged; `content.markdown` stays `None`; the library never emits `\f` (the RC does — §5). `metadata.word_count` is computed on the markup-stripped text in layout mode `[C-reg-11]`.

**Server facts the grammar is designed against** (`KnowledgeBase/knovas-software/app`): headings only via `^(#{1,4})\s+(.+)` → `heading_context` prepended to every embed piece; BM25 strips digits; hierarchical chunking splits each `\f` segment on `\n{2,}` then `\n` then the sentence regex `(?<=[.!?])\s+(?=[A-ZÜÖÄ\d"'(])` (no abbreviation list); chunks > 1800 chars hard-split; embed pieces capped at 256 − 8 = 248 tokens **before `hc: ` is prepended** (D14); page advances per `\f`; Redis keeps only snippet/page/sentence, so tables must live in the text; Qwen3 spends ~1 token per digit.

**Grammar (per page; blocks separated by exactly one blank line)**
```
page        := block ("\n\n" block)*
block       := passthrough | heading | paragraph | list | kv_block | table
passthrough := the plain-mode page text verbatim — iff the page is UNSTRUCTURED (then it is the only block)
heading     := "#"{1,4} " " text        (1–120 chars, ≤ 12 words, no trailing . ; : , ; blank line after)
paragraph   := one physical line, words joined by single spaces, dehyphenated
list        := ("- " text "\n")+          (hanging-indent bullets/enumerators; 2 spaces per ≥ 1.5 em indent)
kv_block    := (kv_line "\n")+            kv_line := key ": " value (" | " key ": " value)*   (≥ 2 lines, consistent anchors; vertical box forms fold the same way)
table       := pack ("\n\n" pack)*        packs ≤ 150 ESTIMATED tokens (D14: 248 − hc_max; raised per tenant once the server subtracts hc)
pack        := header_line "\n" (row "\n")+   header repeated at the top of EVERY pack
header_line := cell (" | " cell)+         stacked headers folded cell-wise ("31.12.2023 CHF")
row         := cell (" | " cell)+         cell := text | key ": " value — the fold only for NUMERIC/date cells with a short distinguishable key; empty cells omitted when every cell has a key, else "-"; "|" inside a cell → "/"
section_row := "#### " label              a label-only row heading ≥ 2 data rows
```
**Structured-page test** (GI-EXTRACT-03): a page is structured iff `detect_tables` finds ≥ 1 region (≥ 3 row-aligned lines sharing ≥ 2 anchors) **or** a kv_block of ≥ 3 lines **or** (OCR pages only) a prose gutter. Otherwise passthrough — byte-identical to plain mode.

**Rules** (unchanged from the judged plan except where marked): R1 headings — digital: size ≥ 1.15 × body or bold-with-whitespace or numbering prefix; OCR: line height ≥ 1.3 × median **plus** one more cue; page-1 letterhead on a structured page becomes the first `# ` line (what "Jahresabschluss von Müller AG" needs). R2 reading order — visual lines → segments (gap > 2 u is a cell break only with leader/≥ 6 u/neighbour support/gutter) → prose gutters (never a cell boundary, never a table) → blocks by union-find within a column → Breuel partial order with the column rule; Tesseract block/par ids as a second column cue on OCR pages. R3 tables — candidate lines, anchors (x1 numeric / x0 text), regions of ≥ 3 lines sharing ≥ 2 anchors, column count by mode, header = leading non-amount lines, vector/raster rulings for multi-line cells, heading-size guard. R4 KV/forms; R5 lists; R6 hyphenation with `HYPH_KEEP_NEXT`; R7 furniture (top/bottom 9 % band repeating on ≥ max(2, 0.4 n) pages; page-number patterns; scanner stamps; first-page letterhead never dropped). **R8 row lint — only on renderer-classified header/row/kv lines (D12)**: no server sentence boundary inside a line (abbreviation whitespace removed; switched off by flag once the server abbreviation guard lands), ≤ 200 est. tokens / 1800 chars else split with "(Forts.)", no empty cell, no ` | ` inside a cell, digits never altered, years/dates stay in rows, no tabs. R9 page markers are the RC's (§5). R10 invariants: no 3+ consecutive newlines, no whitespace-only line, every heading matches the server regex and is followed by a blank line, byte-identical for identical input and for 1 vs N workers, bag-of-words == plain minus furniture/leaders, `len(layout) ≤ 1.5 × len(plain) + 4096`.

**Token cost** (real `knovas_embedding_v1` tokenizer, 90 GT rows): plain cell-per-line 35.6 tokens/row (today), bare pipe 37.4, GFM 42.6 (rejected), fold-compact 48.5, fold-full 56.9 (rejected). Page level: fold 875 tokens/page vs bare 803 (+9 %).

**Example (Bilanz, digital or OCR words):**
```
# Müller AG

## Jahresrechnung 2023

### Bilanz per 31. Dezember 2023

#### Umlaufvermögen

Aktiven | Anhang | 31.12.2023 CHF | 31.12.2022 CHF
Flüssige Mittel | 2023: 1'234'567.80 | 2022: 987'654.30
Forderungen aus Lieferungen und Leistungen | Anhang: 2.1 | 2023: 456'789.00 | 2022: 400'120.00
```

## 5. RemoteController

**M3 (integration)**: `extract_accepts(param)` introspection; env helpers `pdf_text_mode()`, `ocr_options()` (`RC_OCR_ENGINE/DPI/WORKERS/MAX_PAGES/TIME_BUDGET_SECONDS/CACHE_MAX_MB`, time budget derived per `[C-sec-0]`), `RC_EXTRACT_TIMEOUT_PER_PAGE_SECONDS`; **shadow mode per D13** logging `ShadowDiff` (numeric-token Jaccard, row-line ratio, length ratio, ocr_pages, seconds — never text); `page_markers.insert_page_markers` per D11 and `iter_text_chunks_with_location(..., page_markers=True)` (markers applied to the yielded snippet after the heading prefix, one char per text page reserved from the 500 000-char budget; page/sentence numbers unchanged; sidecar built from the **unmarked** text); heading-duplication fix (replace the first line instead of prepending; level cap 4); no `tables` payload for PDFs (`RC_SEND_PDF_TABLES=false`) and for DOCX in layout mode; `context_sidecar` v2 (`k:'row'`, `partial` note) — **the pysbd post-split item is dropped** `[C-reg-7]` (pysbd splits on every newline; a pin test of "20-row pack → 21 sentences" stays); `ocr_cache.py` per §3; small-first upload order; `scripts/backfill_partial_ocr.py`.

**Recording outcomes** (`sync_executor.record_upload_outcome`, GI-EXTRACT-02): library returned with skipped pages → `partial` (listed for the backfill, not re-uploaded each cycle); clean → `synced`; library-flagged unconvertible → `skip:unconvertible`; transient failure, **wall-clock kill (new message prefix that `is_unconvertible_error` does not match)** and `extractor died (exit -9)` → `retry` with a counter and `MAX_EXTRACT_RETRIES` (default 3), after which the file is recorded `partial` and the backfill runs an **OCR-disabled pass** so the text pages land `[C-perf-1][C-sec-0]`. Pinned by `ocr_budget_failsoft.als::RcRecordingMechanism` (mutants `ocr__skip_uncounted`, `ocr__timeout_parks`) and `tests/unit/test_sync_executor_partial.py`. The child also gets `RLIMIT_AS` (~2 GiB) and `RLIMIT_CPU` `[C-sec-2]`.

**M5 (wave)**: `sync_state` gains `content_sha256`; `reingest_wave.py --order skipped,scanned,tables,rest` seeds hashes from `GET /secured/document_hashes` (D15), re-extracts (cache hits), uploads only on mismatch, **paces with the limiter's wait and the server's `Retry-After`** instead of breaking the loop for an hour `[C-perf-8]`, is resumable, reports uploaded/unchanged/partial/failed; on M365 installs it orders by last-known scanned/partial status and skips unchanged ETag/mtime files without downloading `[C-perf-9]`. **Prerequisites**: GI-INGEST-16 pre-embed probe and the §1.10 ACL/KG carry-over fix (`acl_ingest_carryover.als`) deployed on the server; one tenant per night fleet-wide, never "all installs at once" `[C-perf-0]`.

**Observability and pinning** `[C-perf-5]`: `ARG KNOVAS_EXTRACT_REF` pinned to a tag/sha, RC image tag bumped per release (0.2.0 for M0); `rc_build_info{rc_version,knovas_extract_version,text_mode,ocr_engine}` on `/metrics`; `extractor_version` and `text_mode` in `init_document_transmission` metadata (human review: `secure_api.py`) so the server can list "documents produced by version X" per tenant; `SyncRunResult` carries ocr_pages/cache_hits/partial/skip counters, forwarded by the Platform status poll so the Grafana canary panel reads server-side data. Prometheus: `rc_extract_seconds{mode,doc_class}`, `rc_ocr_pages_total`, `rc_ocr_cache_{hits,misses}_total`, `rc_ocr_partial_total`, `rc_ocr_backend_degraded_total`, `rc_extract_rss_bytes`, `rc_skip_unconvertible_total`, `rc_reingest_{uploaded,unchanged}_total`. Host sizing documented (≥ 4 vCPU / 4 GiB free for OCR tenants; `cpus:`/`mem_limit` for the RC in both compose files; `/tmp` tmpfs accounted).

## 6. Platform (docbridge_integration)

Admin ingestion mirrors the RC's kwargs and markers — **but runs extraction in the same guarded child with conservative `OcrOptions` (workers=1, `max_ocr_pages=50`, 60 s budget) and `OMP_THREAD_LIMIT=1` in its Dockerfile**, never in-process in a gunicorn request thread `[C-perf-4]` (routing admin uploads through the RC's `/sync` API is the preferred end state). `context_store._is_thin_location`: a record containing ` | ` or `k=='row'` with ≥ 1 letter-word and ≥ 1 number is not thin; `_CONTACT_LINE` no longer matches `mwst`/`uid` on rows. `preview.py` anchors normalise `' | ' → ' '` and strip fold keys, retrying with the longest cell ≥ 12 chars.

## 9. Flags, rollout, rollback

**knovas-extract**: everything opt-in (`text_mode="layout"`, `ocr=OcrOptions(...)`); default `extract()` output unchanged except the per-page/300-dpi OCR fix, documented as a 0.4.0 behaviour change in CHANGELOG; `SPEC_VERSION` stays 1.3.0 for metadata scalars; **layout mode ships behind its own docs note until spec 1.4.0 defines `text_mode` and the grammar** `[C-sec-18]` (the spec repo is not in this session's scope — open question §11). **RC**: `RC_PDF_TEXT_MODE` plain (default through M3) | shadow | layout; `RC_OCR_ENGINE` auto | tesserocr | cli | mupdf; `RC_OCR_DPI/WORKERS/MAX_PAGES/TIME_BUDGET_SECONDS/CACHE_MAX_MB`; `RC_EXTRACT_TIMEOUT_PER_PAGE_SECONDS`; `RC_PAGE_BREAK_MARKERS` (default true once M3 ships); `RC_SEND_PDF_TABLES=false`; `RC_UPLOAD_ORDER=small_first`; `RC_TESSERACT_LANG` per tenant. **Platform** mirrors the names. **Server**: `INGESTION_EMBED_HC_BUDGET=true` (the hc subtraction, default on after the contract test), optional `INGESTION_SENTENCE_SPLIT_SKIP_ROWS` default off.

**Order**: knovas-extract 0.4.0a1/0.4.0 → RC image (pinned ref, bumped tag) → Platform image → KnowledgeBase (tests + flagged fixes; the server can ship any time). **Per tenant**: (0) GI-INGEST-16 probe + §1.10 carry-over fix on the server before any wave; (1) M0 to all installs; (2) M1 with `plain` to all installs — scanned PDFs change text once, re-ingested as in-place updates, `--order scanned` off-hours; (3) Treuhand pilot shadow 1 week → 10 % 1 week → 100 % + wave; (4) law-firm tenants stay on plain until the scan gate is hard-green for 3 nightlies and a shadow week shows zero numeric-token loss and byte identity; (5) optional tiers only after the real-sample run. **Rollback**: each flag reverts independently; `RC_OCR_ENGINE=mupdf` + `RC_PDF_TEXT_MODE=plain` restore today's text for new ingests; library rollback = previous pinned ref; no server migration involved; the cache is engine/config-keyed so engine changes never serve stale TSV.
