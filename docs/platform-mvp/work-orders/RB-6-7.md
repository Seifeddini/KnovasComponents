## Goal

An agent is a member of roles that is not a person: the Knovas Assistent, or an external agent (Claude Code, Copilot
…) an administrator registers. **Every claim the Core accepts for an agent is signed by the Platform**: the agent's id
as subject, the groups and functions of its roles, narrowed to what the person holds when the agent acts for one.

- The **assistant** goes through the Platform, as it does today, with its own claim (RB-6).
- An **external agent** goes through the **Core's MCP gateway** (`mcp.knovas.ch`). The Platform registers it, makes it
  a member of roles, and hands the Core a pool of its signed claims ahead of use (RB-7, CR-R5). The gateway key is the
  Core's, issued by Knovas and bound to the agent's id (CR-R6); the Platform holds no agent credential.

**Not in this item:** an MCP endpoint on the Platform (dropped); the Core's routes and gateway changes (CR-R5, CR-R6);
data (RB-5); moving direct grants into roles (RB-5, FU-41); Probe (RB-9).

## What to build (the frozen tests pin the interface)

### 1. Migration `P/src/identity/migrations/0028_agents.sql` (RB-6)

New tables only, header in the style of `0027_roles.sql`. The frozen file reads the names in bold.

- **`agents`**: `id` UUID PK (the id the Core's gateway key names); `name` CITEXT unique, 1 to 80 characters; `kind`
  `assistant` or `external`; `on_behalf_of` UUID → `users(id)` `ON DELETE CASCADE` (NULL: acts on its own);
  `created_at`, `created_by`, `revoked_at`, `revoked_by`. Exactly one row of kind `assistant` (a partial unique index);
  only an `external` agent may have `on_behalf_of` (CHECK).
- **`tenant_role_agents`**: **`role_id`** → `tenant_roles` `ON DELETE CASCADE`, **`agent_id`** → `agents`
  `ON DELETE CASCADE`, `added_at`, `added_by`; both ids the key; an index on `agent_id`.
- **No credential:** no column of these tables holds a key, secret, hash or token (frozen).
- The seed, in SQL: one agent `Knovas Assistent` of kind `assistant`, a member of **every role but Administration**.

### 2. `P/src/identity/agents.py`

```python
class AgentError(Exception)             # every refusal; plain German, safe to show, no name
class AgentNotFound(AgentError)         # missing, foreign or malformed id: one answer
class AgentNameTaken(AgentError)
class ProtectedAgentError(AgentError)   # revoking the assistant (it has its switch)

@dataclass(frozen=True)
class Agent:
    id: UUID; name: str
    kind: str                           # "assistant" | "external"
    on_behalf_of: UUID | None           # fixed when an external agent is created
    roles: frozenset[UUID]
    revoked: bool

@dataclass(frozen=True)
class AgentClaim:
    subject: str                        # str(agent.id)
    groups: tuple[str, ...]             # sorted
    functions: tuple[str, ...]          # sorted
    on_behalf_of: UUID | None

class AgentStore:
    def __init__(self, conn)
    def assistant(self) -> Agent
    def list_agents(self) -> list[Agent]                       # the assistant first, then by name
    def get_agent(self, agent_id) -> Agent
    def create_agent(self, *, name, on_behalf_of=None, by=None) -> Agent       # external only
    def revoke_agent(self, agent_id, *, by=None) -> Agent
    def add_to_role(self, role_id, agent_id, *, by=None) -> None
    def remove_from_role(self, role_id, agent_id, *, by=None) -> None
    def roles_of_agent(self, agent_id) -> list[Role]
    def claim_for(self, agent_id, *, on_behalf_of=None) -> AgentClaim
```

Role and group refusals are RB-1's (`ProtectedRoleError` for Administration, `TooManyGroupsError`).

### 3. The claim (RB-6)

- `claim_for`: groups and functions of the agent's roles; for a person (an external agent's fixed person, or the
  person the assistant answers) intersected with `access_groups_of(person)` and `roles_of(person)`; the person must be
  active; a revoked agent has none (`AgentError`); the assistant without a person is `AgentError`; more than 32 groups
  is `TooManyGroupsError`. `add_to_role` and `set_core_group` refuse an agent acting on its own a 33rd group, nothing
  written (the assistant and person-bound agents are narrowed to a person who holds at most 32).
- `PrincipalBroker` (`identity/principal.py`) signs an agent's claim from `claim_for` with the existing signer
  (`identity/assertion.py` unchanged); `sub` is the agent's id.
- **The assistant** wraps its whole answer in `api_client.asserting_for(<the assistant for this person>)`, so every Core
  call of an answer (the search, the doc-fields probe inside it, `/secured/llm/generate`) carries its claim, and each
  declares `actor = {"kind": "agent", "id": "<assistant id>", "on_behalf_of": {"kind": "user", "id": "<person id>"}}`
  (the body of a `POST`; `?actor=` on a graph `GET`). The wrapping must still fail closed:
  `tests/test_assistant_page_routes.py::test_the_real_service_is_wired_and_fails_closed_without_the_secured_api`
  builds the real service on a fake client without `asserting_for` and expects the plain `failed` reply (a first
  reference broke it).
- `RoleStore.create_role` (RB-1) adds the assistant to the new role in its transaction; `set_core_group` also checks the
  role's agents acting on their own.

### 4. Delivery to the Core's gateway (RB-7, CR-R5)

- **The switch** `agents.core_gateway` (`platform_settings.REGISTRY`, choice `aus`/`an`, **`aus`** by default, pinned
  by `AGENTS_CORE_GATEWAY`, in `config/config.yaml`), read through the Resolver. Off, nothing below reaches the Core.
  It stays off until the Core has CR-R5 and, on a client tenant, until «Ein» (founder).
- **What is sent**, for every external agent:
  - live (not revoked, its person active, at most 32 groups): `PUT /secured/agents/<agent id>/claims` with exactly
    `{"claims": [...]}`: **20 claims**, the Core's maximum (frozen), each from `claim_for`, signed by the broker signer with
    a lifetime of **300 seconds**, each its own `jti`;
  - otherwise `DELETE /secured/agents/<agent id>/claims`, never a `PUT`.

  Neither carries a person's `principal_assertion` (the push is the Platform's own call: `_request_no_retry(…,
  as_person=False)`), `access_groups` or an `actor`. The assistant is never sent (it goes through the Platform).
- **When:** `app.extensions["agents"]["sync"]()` sends for every external agent now (frozen seam). A background job
  calls it **every 60 seconds** in one gunicorn worker at a time (`pg_try_advisory_lock`), on a connection of its own.
  Creating, revoking, and adding or removing an agent on a role through the pages of § 5 send for that agent **at
  once**, after the change is committed. Role and person changes made elsewhere (RB-4's pages, the people page) reach
  the Core at the next minute; the pool's claims end within 300 seconds in any case.
- **Failures** (the Core answers 404 because it lacks CR-R5, 409 `not_brokered`, 5xx, no connection): logged at WARNING
  with the agent's id, the status and the exception's class; never raised into a page or the job; never a claim in a
  log line or an exception.
- **New client methods** in `knovas_client.py`: one for `PUT`, one for `DELETE` (names yours).

## Rules

1. **New tables only**; no change to an existing table, migration or RB-1's interface. `identity/roles.py` changes in
   the two places of § 3 only.
2. **One claim for every agent** (§ 3). A person's direct group grants reach no agent (FU-41). No agent joins
   Administration.
3. **The Platform holds no agent credential** and never sees the gateway key.
4. **Every claim delivered is the claim `claim_for` gives at that moment**, signed by the Platform; never wider, never
   longer than 300 seconds, never two with one `jti`.
5. **32 groups**: no claim with more is signed or sent; such an agent gets `DELETE`.
6. **Revoking acts at once** on the Platform and, with the switch on, at the Core (`DELETE` in the same request).
7. **No customer text** in an audit row or log line (FU-14, PR #55): no agent name, person name, question, passage or
   claim; ids, counts, statuses and class names only. `agent.created`, `agent.revoked`, `agent.role_added`,
   `agent.role_removed` are written by id (`actor_user_id` = `by`) in the change's own transaction.
8. **Nothing is written to a tenant at start**, and with the switch off nothing reaches the Core.
9. **One transaction per change**; malformed, foreign and missing ids are one `AgentNotFound`.

## What acts when

| Core state | What the pilot gets |
|---|---|
| today | the assistant's claim is signed and logged, and narrows nothing; agents are registered and members of roles; `AGENTS_CORE_GATEWAY` off |
| CR-R1 («Ein» possible) | the assistant reads only what its roles and the person hold |
| CR-R5 | switch on: the Core holds each external agent's pool (on a `brokered` tenant) |
| CR-R6 | an agent-bound gateway key works: the agent reads through `mcp.knovas.ch` what its roles (and its person) allow |

**Before that**, on client tenants agents stay off (founder: "only after «Ein»"). The Knovas GmbH pilot keeps today's
access (the internal MCP server, or a company key of the gateway).

**A client with only external agents and no assistant:** `ASSISTANT_ENABLED=aus`, `AGENTS_CORE_GATEWAY=an` (frozen):
`/fragen` answers 404 and the delivery runs. Nothing in the delivery depends on the assistant, its provider or its key.

## Decisions this order takes (draft: for the coordinator and the founder to confirm before the tests are frozen)

1. **A pool of claims** (20 a push, the Core's maximum; 300 seconds; a push a minute; so at most 20 upstream calls
   a minute per agent) rather than the gateway signing per call (design § 5).
2. **The gateway key is issued by Knovas** with the agent's id (`manage_mcp_keys --agent`, CR-R6); the Platform shows
   the id. Self-service later.
3. **The paths** `/admin/agents…` and `/admin/roles/<id>/agents/…` (English, like RB-3/RB-4's `/admin/roles`).
4. **The assistant joins every role but Administration**, also later ones; an administrator may take it out of a role;
   no agent joins Administration; direct grants reach no agent (FU-41).
5. **The assistant's claim on every Core call of an answer**, `/secured/llm/generate` included.
6. **Role and person changes made outside the agent pages** reach the Core at the next minute (not at once).
7. **`AGENTS_CORE_GATEWAY` off by default.**
